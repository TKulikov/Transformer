# Полномасштабные тесты живой памяти на диалогах

Статус: **схема утверждена пользователем 2026-11-17; код и CPU-проверки готовы**.
GPU не запускался; следующий шаг — дневные контрольные батчи по решению пользователя.

## Цель и протокол

Сравнить живую память с конкурентами и с собственными настройками на одном
`main`-корпусе: 48 диалогов, 24 комбинации осей × длины 100 и 200 ходов.
Все ветки используют Qwen3.5-4B bf16, greedy, budget 128, 32 новых токена,
один warmup и пять чередующихся повторов end-to-end латентности.

Минимальная единица — диалог × все стратегии ветки. Каждая ветка независима,
пишет `manifest.jsonl`, JSON батчей и `INTERIM.md`, продолжается по готовым
батчам. Одновременно запускается только одна ветка.

## Три независимые ветки

### `full_core`: конкуренты

- `classic_kv_full`;
- `sparse_sliding_128`, `sparse_topk_128`, `snapkv_128`, `pyramidkv_128`;
- `v4_kv_mid`: только K/V-инъекция, 32 слота, банк 512;
- `v4_kv_mid_dyn`: динамический гейт cos >= 0.5, 1–32 слота.

7 стратегий. Первый контрольный батч измерен: **1,97 ч (118,5 мин)**; ночные
четыре дополнительных батча по этому замеру ≈ **7,9 ч**.

### `full_self`: сравнение с собой

- `classic_kv_full`, `pyramidkv_128` — внутренние контроли;
- `v4_kv_mid_k8`, `v4_kv_mid_k16`, `v4_kv_mid`, `v4_kv_mid_k64` — ширина
  инъекции 8/16/32/64;
- `v4_kv_mid_dyn` — динамическая ширина;
- `v4_kv_mid_s128`, `v4_kv_mid`, `v4_kv_mid_s1024` — банк 128/512/1024;
- `v4_kv_mid_no_ttl` — статический банк без TTL.

10 стратегий. Контрольный батч ≈ 2,6 ч; ночные три дополнительных батча
≈ 7,8 ч. Все варианты живой памяти здесь без текстового RAG.

### `full_rag`: раздельные текстовые каналы

- `rag_text_only`: last-layer, без центрирования;
- `rag_last_centered`: last-layer + глобальный центроид;
- `rag_latent_mid`: mid-layer, без центрирования;
- `rag_mid_centered`: **mid-layer + глобальный центроид**, без K/V;
- `rag_bank_key`: ключи из слотов живого банка, без K/V;
- `rag_bank_dev`: кластерный anchor/deviation-поиск по живому банку, без K/V;
- `v4_rag_kv_mid`: двухканальный mid-RAG + K/V;
- `classic_kv_full`: полный контекст.

8 стратегий. Контрольный батч ≈ 2,1 ч; ночные три дополнительных батча
≈ 6,3 ч. Все RAG-стратегии, кроме явно названной `v4_rag_kv_mid`, не инжектят
K/V и различаются только устройством банка/ключей и центрированием.

## Запуск по одному

Из корня проекта:

```bash
# Дневные контрольные точки: по одному новому батчу, не автоматической цепочкой.
scripts/run_dialogue_fullscale.sh core gate
scripts/run_dialogue_fullscale.sh self gate
scripts/run_dialogue_fullscale.sh rag gate

# Просмотр очереди и стратегий без GPU и без записи результатов.
scripts/run_dialogue_fullscale.sh core dry-run
scripts/run_dialogue_fullscale.sh self dry-run
scripts/run_dialogue_fullscale.sh rag dry-run

# Ночь: продолжить ОДНУ выбранную ветку после просмотра её INTERIM.md.
scripts/run_dialogue_fullscale.sh core night   # 4 новых батча
scripts/run_dialogue_fullscale.sh self night   # 3 новых батча
scripts/run_dialogue_fullscale.sh rag night    # 3 новых батча
```

`gate` всегда выполняет один следующий незавершённый батч. `night` добавляет
указанное число новых батчей к уже готовым, а не повторяет дневной. Оценки
относятся к 100-ходовым диалогам; фактическое ETA после первого батча показывает
`INTERIM.md` и dry-run. Вторая половина `main` содержит 200-ходовые диалоги и
потребует отдельной оценки окна.

Перед реальным запуском лаунчер проверяет занятую VRAM и отказывается стартовать
при использовании более 1 GiB. Порог можно явно изменить переменной
`MAX_VRAM_USED_BYTES`; GPU между ветками не делится.

## Изменение настроек после дневной проверки

Новые `run_config.json` хранят полные `Strategy.describe()` и протокол. Resume с
другими настройками или числом повторов завершится ошибкой: нельзя молча смешать
два условия в одной серии. После содержательной правки нужно изменить `RUN_ID` в
лаунчере (например, `full-rag-v2`) и начать новую серию. Старые результаты не
удаляются и не перезаписываются.

## Критерии контрольной точки

Перед ночным продолжением проверить: статус батча `done`, отсутствие ошибок в
манифесте, отсутствие NaN/аномальной латентности, ожидаемый размер живого банка,
ненулевую инъекцию у K/V-стратегий и отсутствие `kv_steps` у чистых RAG. Для
`rag_mid_centered` сверить `rag_layer=mid`, `rag_centered=true`, `memory_kv=false`;
для `rag_bank_dev` — `rag_key_source=bank_dev`, `memory_kv=false`.
