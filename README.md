# tmem — память + KV-кэши в трансформерах

Промышленная переработка ноутбука `Transformer(1).ipynb` в пакет Python с
тестами и бенчмарком. Ноутбук исследовал идею **внешней ассоциативной памяти**
(`Memory` со слотами, косинусным ретривингом, TTL-вытеснением и слиянием
дубликатов), инжектируемой в слои T5/GPT-2/Qwen2 через хуки, и сравнивал
её с «полным контекстом» по токенам/латентности/качеству ответов.

Что добавлено сверх ноутбука: честное сравнение с **классическим KV-кэшем**
и **разреженным KV-кэшем** (sliding/StreamingLLM-стиль и topk/H2O-стиль) на
явном цикле декодирования, плюс сверка ответов с заранее заготовленными
вопросами (keyword-scoring).

## Структура

| Модуль | Назначение | Cells ноутбука |
|---|---|---|
| `tmem/memory.py` | `Memory` + `CorrectionLayer` (алгоритм 1-в-1, исправлен баг с дублями слотов) | 0 |
| `tmem/hooks.py` | хуки инжекции памяти: конкатенация в энкодер T5 (+маска), аддитивное влияние в декодеры | 0, 1, 2 |
| `tmem/kvcache.py` | политики кэша: `classic` (неограниченный) и `sparse` (`sliding`, `topk`) + трекер важности H2O | — (новое) |
| `tmem/compat.py` | совместимость с внутренним устройством `DynamicCache` разных версий transformers | — (новое) |
| `tmem/generate.py` | управляемый цикл генерации с метриками (длина кэша, латентность, пик памяти) | 3, 4, 5, 6, 8, 10 |
| `tmem/dialogue.py` | сетка стратегий `контекст x память x кэш` и прогон диалоговых сессий | 4, 5, 6, 8, 10 |
| `tmem/qa.py` | заготовленные вопросы с эталонными ответами + сессии «игла в стоге сена» | (вместо ad-hoc промптов) |
| `tmem/metrics.py` | метрики качества (новизна, strict) и keyword-скоринг | 6, 8, 10 |
| `tmem/models.py` | реестр моделей (gpt2 / qwen2-1.5b / t5-base), крошечные офлайн-модели для тестов | 2, 5, 6, 8, 10 |
| `tmem/semantic.py` | **v2**: EMA-слияние (k, crit=0.95), RAG-банк фактов с upsert, gist-ретривинг, метрики тона/дегенерации | — (итерация по итогам стресс-теста) |
| `tmem/stress.py` | стресс-батарея: длинные сессии с фактами/обновлениями/парафразами, adversarial-«близнецы», анализ Парето тон×вычисления | — |
| `tmem/plotting.py` | графики по **реальным** замерам (в ноутбуке последние два графика были «симуляцией») | 7, 9, 11 |
| `tmem/cli.py` | бенчмарк: `python -m tmem.cli --model gpt2 --device cuda` | — |

## Запуск тестов

```bash
.venv/bin/python -m pytest -q                 # ~101 unit-тест, CPU, офлайн
.venv/bin/python -m pytest -m integration -q  # реальный GPT-2 на CPU (нужна сеть)
.venv/bin/python -m pytest -m gpu -q          # ТОЛЬКО по согласованию, ROCm/CUDA
```

Маркеры `integration` и `gpu` исключены из прогона по умолчанию
(`pyproject.toml → addopts`).

### Что проверяют тесты

* **память**: хранение/гейт активности, слияние дубликатов, «серая зона»
  схожести, лимит ёмкости, TTL (+2 бонус за хит, −1 за запрос, вытеснение),
  консистентность Buchkeeping (регрессия бага ноутбука с `__empty_slots`),
  детерминизм, границы `count`;
* **хуки**: форма/маска конкатенации энкодера, сброс position_bias,
  аддитивный путь декодера (включая fp16), passthrough при пустой памяти,
  регистрация на реальных блоках GPT-2/T5;
* **KV-кэш**: эквивалентность классического кэша пересчёту без кэша
  (токен-в-токен!) — и на крошечных моделях, и на настоящем GPT-2;
  разреженный кэш с огромным бюджетом == классический; скользящее/топковое
  вытеснение держит бюджет, не ломает генерацию и экономит attention-работу;
* **диалоги**: все 6 стратегий на обеих архитектурах (causal и encoder-decoder),
  экономия токенов у window/hybrid, накопление памяти, скоринг probing-вопросов;
* **QA/метрики/CLI**: keyword-скоринг, корректность эталонов, прогон `answer_questions`.

## Бенчмарк (после одобрения запуска на видеокарте)

```bash
.venv/bin/python -m tmem.cli --model gpt2  --device cuda --budget 128
.venv/bin/python -m tmem.cli --model qwen2-1.5b --device cuda --budget 128 --max-new-tokens 32
.venv/bin/python -m tmem.cli --model t5-base --device cuda
# большая батарея: 107 ходов, 24 вопроса, 16 фактов + смены (Qwen3.5-4B, bf16, ~8 GiB VRAM):
.venv/bin/python -m tmem.cli --model unused --battery100 --models qwen35-4b --device cuda --dtype bfloat16 --out results/battery
.venv/bin/python scripts/summarize_stress.py results/battery
```

Стратегии: `no_cache_full`, `classic_kv_full`, `sparse_sliding`,
`sparse_topk`, `window_only`, `window_hybrid_memory`. Выход: `results/*.json`
(токены, длина кэша, латентность, quality, probe-scores) и PNG-графики.

## Примечания по железу

Видеокарта — **AMD Radeon RX 7900 XTX (Navi 31)**: NVIDIA/CUDA нет, PyTorch
нужен в ROCm-сборке (`pip install torch --index-url
https://download.pytorch.org/whl/rocm6.x`), устройство при этом называется
`cuda`. Текущий `.venv` — CPU-сборка torch 2.15; для прогонов на GPU её надо
заменить на ROCm-сборку (загрузка нескольких ГБ — шаг только с одобрения).

## Ограничения (задокументированы честно)

* sparse-кэш для T5 чистит только decoder self-attention кэш; относительные
  позиции T5 корректны при `sliding` (окно остаётся связным), при `topk`
  возможны смещения bias;
* `topk`-важность — накопленная сумма внимания (H2O-подобная), attention
  включается через `eager`-реализацию;
* метрики качества — эвристики ноутбука (лексика), семантической оценки нет;
* `Memory.check` (гейт по сумме окна) унаследован из ноутбука как есть —
  он чувствителен к знаком активаций; порог вынесен в
  `Strategy.memory_window_crit`.
